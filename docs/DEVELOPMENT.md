# Development

## Requirements

| Tool | Needed for |
|---|---|
| C compiler: MinGW-w64 `gcc`, or the clang `gcc.exe` bundled with OMNeT++ 6.x (Windows; `build.bat` finds it), or `gcc` + `make` (Linux) | firmware, simulator, C tests |
| Python 3.10+ with `numpy`, `matplotlib` (`python -m pip install -r requirements.txt`) | traces, experiments, analysis, Python tests |
| MATLAB (optional) | filter cross-check |
| Arm GNU Toolchain + Renode 1.17 portable in `%USERPROFILE%\tools\renode\` or `RENODE` set (optional) | Cortex-M4 emulation |

## Build and test

| Windows | Linux | What it does |
|---|---|---|
| `build.bat` | `make` | builds `build/sensor_node` and `build/test_firmware` |
| `build\test_firmware.exe` | `./build/test_firmware` | C unit/integration tests |
| `run.bat` | `make test` | build → C tests → traces → 90 runs → analysis → plots → 100-run seed study → Python tests (about 2 min) |
| `run.bat matlab` | – | also runs the MATLAB filter check |
| `run_renode.bat` | – | generates `trace_data.h`, cross-compiles the STM32F4 image, runs it in Renode |
| `python -m unittest discover -s tests -p "test_*.py"` | same | Python tests only (traces must exist) |

## Running the simulator

```bat
python python\generate_data.py
build\sensor_node.exe --profile water --strategy adaptive --trace experiments\traces\water_sudden.csv --out build
build\sensor_node.exe --config experiments\configs\node.ini
build\sensor_node.exe --dump-profile water
```

**Options.**

- `--strategy`: `fixed`, `adaptive_tx` or `adaptive`.
- Channel: `--seed`, `--loss`, `--ack-loss`, `--corrupt` (probabilities 0–1) and `--sf` (7–12).
- Other: `--stable-s`, `--storage-cap` and `--node-id`.

Out-of-range values are rejected.

**Trace format.** The trace is a CSV with columns `t, v0..v3, f0..f3, link`; extra columns are ignored.

- `t` must start at 0, have a constant whole-second step, and stay below 2^31 s.
- `f` is the fault code: 0 ok, 1 missing, 2 stuck.
- `link` is 1 when the radio link is up.
- An empty value counts as a missing reading; `inf`/`nan` are rejected.

Malformed rows are rejected with the line number.

**Outputs.** Each run writes `samples.csv`, `tx.csv`, `gateway.csv`, `storage_dump.csv`, `summary.json` and `flash.bin` (the emulated storage) to `--out`.

## CI

`.github/workflows/ci.yml` has two jobs:

- **`test`** has read-only access. It runs `make test` on Ubuntu for every push and pull request to `main`.
- **`publish-results`** runs only after `test` passes, and only on pushes to `main`. It is the only job with write access, and it commits the regenerated results.

MATLAB and Renode are not available in CI.

## Extending

- **New profile:** copy `firmware/profiles/profile_soil.c`, give it a new id and name, and add it to `PROFILES[]` in `profile_registry.c`. Then add the matching virtual board in `vdev_load_board()` (`simulation/sensors/virtual_sensors.c`) and an entry in `experiments/configs/experiment_config.json`.
- **New sensor:** write `probe/read_raw/convert` in `firmware/drivers/`, export a `sensor_driver_t`, reference it from a profile channel, and add the inverse model to `virtual_sensors.c`. Add a decode test to `test_registration_and_drivers()`.
